# RCA — Redeploy build failure (run db789b07-1c46-425a-ab91-a26ce9b9cd65)

## Summary
The `build_image` step failed during the backend pip install. The build is a **source-level failure**, not a manifest or infra problem. A redeploy without a source change will fail identically.

## Failed step
- Step: `build_image` (Cloud Build), stage `backend-build`
- Command: `pip install --no-cache-dir --no-dependencies -r /app/backend/requirements.txt`
- Retried 3x, all failed → terminal.

## Root cause
`backend/requirements.txt` line 58 pins a package that does not exist:

```
lintiq==0.1.3
```

Build error (verbatim):
```
ERROR: Could not find a version that satisfies the requirement lintiq==0.1.3 (from versions: none)
ERROR: No matching distribution found for lintiq==0.1.3
```

Verified in the eph sandbox against the run's pulled source:
- `grep -n -i lintiq backend/requirements.txt` → `58:lintiq==0.1.3`
- `pip index versions lintiq` (with the Emergent private extra-index `https://d33sy5i8bnduwe.cloudfront.net/simple/` configured) → `ERROR: No matching distribution found for lintiq` — the package exists in **neither** PyPI **nor** the Emergent private index.
- `grep -rn -i lintiq backend --include=*.py` → **no matches** — the package is not imported/used anywhere in the backend. It is a phantom, unused pin.

Context: prior redeploys of this job (e.g. run 2817dc4b) built successfully; this `lintiq==0.1.3` line was introduced since then and breaks the build.

## Fix (Code — E1 to apply in the source environment)
Remove line 58 from `backend/requirements.txt`:

```
- lintiq==0.1.3
```

No code references it, so removal is safe and requires no other change. After removing it, re-trigger the deploy.

(If `lintiq` was intended to provide real functionality, it would need a correct, published package name/version — but nothing in the backend imports it, so removal is the correct fix.)
